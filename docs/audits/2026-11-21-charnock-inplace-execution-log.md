## 2. Что именно произошло

### 2.1. 02: страница исправлена, receipt — через reconcile

- `02-execute` (44948657654, `f66bc0b`) сделал один `editPage`; живая страница получила `[…]` в `q-19`.
- Пост-проверка потребовала полного совпадения **структуры** узлов, а Telegraph вернул семантически тот же документ с иной нормализацией. Скрипт остановился как `UNCERTAIN`, receipt не записал. Это **не** откат и не второй POST.
- PR #1057 заменил строгую проверку на проверку целевых blockquote + неизменности видимого текста остальных узлов; любой POST-путь теперь пишет `UNCERTAIN`-receipt, а read-only `reconcile` подтверждает уже применённую страницу.
- `02-reconcile` (44951152546, `51ab337`) сделал только `getPage`, подтвердил, что все after-блоки на месте, и записал `VERIFIED_IN_PLACE_RECONCILED` (661 B). Повторного `editPage` не было.

### 2.2. 13: первый execute остановился до POST

- `13-execute` (44951624473, `51ab337`) остановился на контракте: `q-3` и `q-11` в живой странице — **одни blockquote из двух абзацев**, а контракт содержал только целевой абзац. Проверка «ровно один blockquote» не нашла совпадения; POST не выполнялся, receipt не создавался, страница не изменялась.
- PR #1058 закрепил полные before/after для `q-3` и `q-11`, сохранив второй абзац без изменений.
- `13-dry-run` (44952096632, `143cb3f`) — success; `13-execute` (44952296684, `143cb3f`) — success, receipt 738 B.

## 3. Границы и гарантии

- **Тот же URL.** Скрипт перед POST проверяет `path`, автора и список контента; после POST — `path`, `url`, `title`, `author_name`, `author_url`, `image_url`, `description`. Любой дрейф → `UNCERTAIN`, без retry.
- **Один POST.** `editPage` вызывается ровно один раз; ошибка/таймаут не повторяются.
- **Никаких новых страниц.** В workflow и скрипте нет `createPage`.
- **Никакого Telegram.** В workflow нет `sendMessage` и нет bot-token; #13 остаётся в **TELEGRAM SEND HOLD**.
- **Один receipt на запуск.** Execute-шаг проверяет, что в receipt-каталоге ровно один `*.json`; reconcile — тоже.
- **Потолок.** Для 02 авторизованный JSON — 62 429 B (запас 3 107 B до 65 536 B); для 03 — 60 923 B. Фактические POST прошли, `CONTENT_TOO_BIG` не было.
