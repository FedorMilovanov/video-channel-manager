# Мастер-промпт · YouTube-пакет к песне — The Legendary Poet

Канал: `youtube.com/@TheLegendaryPoet` · **версия 3.1** · правила владельца от 2026-11-01.

## Назначение и приоритет

**Обязательный контракт для нового ручного пакета** канала `legendary-poet`. До создания текста прочитать этот документ, `youtube-copy-authoring-standard.md`, `youtube-description-rendering-standard.md`, `youtube-editorial-standard.md` и `operations/legendary-poet-description-profile.md`. Этот документ задаёт **форму нового пакета** вместо прежней модели «первый абзац, затем ссылки»; не переоформляет автоматически старые публикации и не меняет guards/provider-код. За точные IDs и project identity отвечают канонические реестры. Явный запрос владельца на отдельный элемент ограничивает объём ответа, а не отменяет правила оформления этого элемента.

## 1. Выход: ровно пять копируемых блоков

Вход: поэт, точное произведение/инципит, проверенный год, подтверждённое содержание ролика.

При запросе **полного пакета** выдать в строгом порядке:
1. **Пять названий**, по одному на строке.
2. **Description**, готовый целиком.
3. **SHORTS** (500–600 символов).
4. **ЗАКРЕП** (500–900 символов).
5. **ТЕГИ: ...** (одна строка).

Каждый пункт — отдельный тройной блок кода **без названия языка**; внутри только готовый копируемый текст. **Ничего до первого блока и ничего после `ТЕГИ:`**. Не вставлять объяснения, номера вариантов, ссылки на источники, комментарии ассистента, экранирование Markdown или служебные метки внутрь блоков. В альтернативном интерфейсе допускаются пять самостоятельных буквально копируемых блоков. При запросе только одного компонента выдавать его, не навязывая остальные четыре.

**Никакого угадывания содержания:** если в Short прочитана одна строфа, не утверждать, что озвучено полное произведение. Не утверждать, что видео прослушано, если звук не проверен.

## 2. Пять названий

Шаблон: `[название / точная строка] ⚡ [КЛЮЧЕВАЯ СТРОКА КАПСОМ] ⚡ [Имя Поэта]`. Допускается 1–3 сегмента, обычно 2–3, максимум два разделителя ` ⚡ ` с пробелами. Обычный русский регистр для первого и последнего сегментов; CAPS только для акцентного среднего. Автор — `Сергей Есенин`, `Владимир Маяковский` и т. п.; подтверждённый год можно добавить после имени через запятую. Первое название/инципит — в «ёлочках» при необходимости.

**Пять разных типов:** поисковый (автор + произведение), ключевая строка с многоточием, конкретный образ/тема, лозунг CAPS, характер исполнения/версия **только если подтверждена записью**. Каждый ≤70 символов. Использовать узнаваемые точные цитаты, не выдумывать строк, исполнения и версии.

Запрещены: `|`, `+`, `&`, `(Official Video)`, Title Case, CAPS целиком, кликбейт-цифры, более одной тематической эмодзи, «нейросеть», «AI», «Suno», «нейромузыка», ложные обещания. Тематические 🖤 ❤️ 📖 🎭 🎬 возможны вместо ⚡ только если соответствуют стилю канала. Дефис и тире разрешены.

## 3. Description

**Строгий порядок нового пакета 3.1:**

```
Плейлист «[Поэт]»: https://www.youtube.com/playlist?list=[проверенный_ID]
Плейлист «Поющие Поэты»: https://www.youtube.com/playlist?list=PLy9lLJfoq3uaxXMvilfZIYVXsf4fY18T8

*VK:* https://vk.ru/thelegendarypoet
*Телеграм:* https://t.me/thelegendarypoet
*Рутуб:* https://rutube.ru/channel/74579453/
*Сайт:* https://thelegendarypoet.ru/

[6–8 содержательных абзацев]

[8–10 тематических хештегов]
```

Первые две строки — плейлисты без разметки, далее соцблок в фиксированном порядке, затем текст, затем хештеги. URL только открытые, без `[текст](url)`; в абзацах ссылок нет. Для неизвестного авторского плейлиста — STOP и проверка, а не выдуманный ID или публикуемый placeholder. **Ссылка на плейлист в описании Shorts не означает включения Short в плейлист.**

Описание **3500–4600 символов всего** (включая ссылки/пробелы/хештеги), **6–8 смысловых абзацев по 300–700 символов**. Первый **литературный абзац после соцблока** не содержит `*`/`_` и не является рекламным. История текста, первая публикация, варианты редакции, контекст года, стихотворная форма, образная система, тональность и конкретный финал. Не допускать одинаковых шаблонных абзацев.

**Без** рассказов о записи, аранжировке, инструментах, жанре, генерации, голосе, технике, просьб подписаться, голословных оценок, выдуманных авторских чувств и обстоятельств. Запрещены речевые костыли: «не только… но и», «важно понимать», «стоит отметить», «как известно», «поистине».

Оформление: **3–4 акцента `*жирный*` и 2–3 `_курсив_`**; по одному маркеру каждого типа, без вложений/двойных звёздочек и без маркеров в первых двух строках, SHORTS, названиях и тегах. Пунктуация, завершающая выделенную фразу, **внутри** обёртки: `*«Я сердцем никогда не лгу».*`; связывающее внешнее тире — снаружи. «Ёлочки» снаружи, „лапки“ внутри. YouTube Studio может показывать **сырой текст** с маркерами, а страница просмотра — форматированный текст; сохранять буквальные маркеры при копировании, не утверждая без проверки, что они всегда видны зрителю.

Хештеги: 8–10, CamelCase, без пробелов внутри, только релевантные, в самом конце.

## 4. Источники и факт-слои

Прежде чем писать историю создания/публикации/дату/посвящение/цитату, проверить **не менее двух независимых источников**, хотя бы один академический (ПСС, комментарии, хроника, рукопись). Различать: **факт** (издание), **свидетельство** (воспоминания/письмо, с атрибуцией), **датировку** (чья и насколько точная), **интерпретацию** (не выдавать за авторский замысел). Не выдумывать точный день по известному году. Сохранять вне копируемых блоков внутренний source ledger с URL, изданием, страницей и границами утверждения. Парафраз/синтетическая речь не становятся прямой цитатой автора.

## 5. SHORTS

**500–600 символов**. Первая строка — суть; вторая — один проверенный факт (год, публикация, страница). Затем две строки релевантных плейлистов с **точными проверенными ID**, далее 3–5 хештегов. Без `*`, `_`, соцблока, эмодзи, призывов и выдуманного полного чтения.

## 5a. Poetry-quote Shorts — проверка автора, редакции и речи (2026-11-10)

Это узкий **owner-requested режим** для 9:16 Shorts, в которых оживлённый поэт читает цитату. Он не заменяет базовый пятиблочный пакет v3.1, не меняет структурированный comment-v2 и не применяется автоматически к существующим роликам. Прямой запрос владельца «короткое описание + закреп с полным стихом + отдельный подробный исторический комментарий» имеет приоритет **только по составу и длине** этих материалов, не по требованиям достоверности, ссылок и доступа.

**Обязательный preflight до генерации изображения, озвучивания и метаданных:**

1. Создать внутреннюю запись `author | exact_work | exact_excerpt | edition | edition_version | date_basis | primary_text_url | corroboration_url`. Тематическое сходство, популярная цитатная карточка или подпись на картинке не доказывают авторство. Пример риска из 2026-11-10: «Кавказ подо мною. Один в вышине» — **А. С. Пушкин** (РВБ, академическое собрание), **не** Лермонтов. «Тебе, Кавказ, суровый царь земли» — **М. Ю. Лермонтов**. Если доказательство не найдено, `STOP: attribution_unverified`, не создавать речь с предполагаемым автором.
2. Выбрать **одну** проверенную редакцию. Текст ролика, «полный стих» в комментарии и историческая датировка должны однозначно соотноситься с ней; не склеивать варианты. Например, Лермонтов, редакция **1837**: «Я снова посвящаю стих небрежный»; редакция **около 1838**: «Я посвящаю снова стих небрежный». Для черновика честно писать «весь сохранившийся текст редакции», сохранять обозначенные изданием лакуны/квадратные скобки. Различать `verbatim_edition`, `spoken_text` и нормализованное написание (например, ради читаемости); нормализация не объявляется дословным академическим текстом.
3. Проверить **непрерывность и завершённость** выбранного фрагмента, границы строфы, количество строк и точные слова. Не выдавать фрагмент за полное стихотворение; не приписывать цитату другому автору, даже если тема (Кавказ, осень, природа) общая. Для исторической справки требуются два независимых источника, как в § 4.
4. Составить `pronunciation_notes` для **всех** двусмысленных ударений, архаизмов, собственных имён и омографов в конкретном контексте. Например, «И осени́ вершиной белоснежной»: **осени́** — повелительное наклонение от «осенить», ударение на последнем «и»; не «о́сени» и не «осе́ни». Передать ударение в читаемом тексте/поддерживаемом словаре TTS и проверить **реально сгенерированную полную аудиодорожку**, дикцию, отсутствие обрезанных концов слов/повторов и фактический lip-sync. Без прослушивания оставлять `audio_unverified`: обещание «идеального произношения» в промте доказательством не является.
5. Сверить длительность по **реальной** русской речи и паузам. Четыре строки могут не уместиться разборчиво в 10 секунд; при дефекте выбрать согласованный короткий непрерывный отрывок или длительность, не ускорять речь до неразборчивости. Внешность/возраст/исторические детали также сверять с выбранным периодом, а не переносить модельный возраст из чужого промта.

### Язык промтов для генеративного ИИ (правило владельца, 2026-11-12)

- Промты-инструкции для моделей генерации и оживления изображений/видео писать **на английском языке**: композиция, движения, тайминг, камера, свет, эмоции, lip-sync, ограничения и негативные инструкции. Это правило относится к тексту промта, а не к языку произведения или публикации.
- **Русский оригинал стихотворения, точные строки для озвучивания и любая подлинная русская речь остаются исключительно на русском, кириллицей.** Не переводить, не перефразировать и не «улучшать» их ради англоязычного промта. Помечать как `Spoken Russian text (verbatim)` и требовать `Speak Russian only; do not translate the words`.
- **Пояснения к русским ударениям давать на русском языке**, показывая исходное слово, конкретную ударную гласную и её положение: `сторожа́ — ударение на последнюю «а»`, `зверьё — ударение на «ё»`. Оформлять отдельной русскоязычной секцией `Ударения и произношение`, даже когда окружающий промт на английском; не заменять русские буквы английской транслитерацией.
- В тексте для зрителя сохранять `verbatim_edition` без диакритики, для TTS использовать отдельные `tts_lines` и `pronunciation_notes`. Не выдавать добавленные ударения за дословное академическое написание.
- При лимите от владельца (например, **до 2500 символов**) считать **весь копируемый промт**, включая русский текст, ударения и негативные инструкции. Не считать качество речи доказанным до прослушивания аудиодорожки: `audio_unverified`. Сопоставлять 10-секундный хронометраж с фактической длиной русского произнесения.

**Если владелец отдельно просит три текстовых элемента:**

- `SHORTS_DESCRIPTION` — краткая формулировка точного произведения, автора, статуса отрывка, один проверенный факт; актуальные уместные плейлисты и 3–5 хештегов. Стандартные 500–600 символов § 5 не меняются глобально; прямое «сделай короче» допускает осознанное локальное исключение.
- `PINNED_COMMENT_CANDIDATE` — первый **top-level** комментарий, полный текст **именно выбранной редакции** (если доступен и разрешён), короткая история и канонические ссылки **в конце**. При прямом запросе полного стихотворения обычные 500–900 символов и обязательный вопрос с двумя вариантами не применяются; фактологическая точность, права и лимиты YouTube обязательны.
- `HISTORY_COMMENT` — второй, содержательно **новый** комментарий об автографах, свидетельствах, публикациях, историческом контексте, редакциях и значениях слов. Не повторять стих целиком и не превращать предположение в факт; хранить библиографию и границы утверждений. Можно предложить как ответ на первый комментарий, но реальный parent ID и разрешение на операцию проверяются отдельно. На YouTube **один** закреп; API-создание комментария не равно Studio pin. Не создавать дубль при неизвестном результате.
- Плейлисты и сайт брать из `docs/operations/legendary-poet-description-profile.md` / реестра идентичности. «Ожившие Цитаты Поэтов» подтверждён поиском YouTube с фильтром по точному каналу `UC-78ys2S3cQ3lpqgXfo-SvQ` (2026-11-13): playlist ID `PLKcHOT3kiGT4`, канал-владелец The Legendary Poet. Для новых provider writes повторно проверять доступность и принадлежность каналу. Для остальных плейлистов без свежего подтверждения — `link_unverified`, без догадок.

**Прозрачность исследования:** требование владельца «50+ материалов» означает проверенные и классифицированные адреса с названием, URL и выводом, **не** 50 автоматически независимых научных исследований. Отдельно отмечать академический текст, архив, текстологию, научное исследование, популярную перепечатку и контекст; повторения не считать самостоятельными подтверждениями. Публичное короткое описание не превращать в каталог из десятков URL.

**Выдача/безопасность:** по запросу владельца текстовые элементы отдать в отдельных буквально копируемых блоках; вне блоков перечислить неразрешённые расхождения, источники и статус аудиопроверки. Обычный механический валидатор v3.1 проверяет форму, но **не** авторство, версию, ударение, полное звучание или факт опубликования/закрепления. Это **только редакционный стандарт**: никакого YouTube, Instagram или VK write без самостоятельного точного одобрения и независимого postflight.

**Текстологический контроль на реальном кейсе:** в электронном четырёхтомнике РВБ (https://rvb.ru/19vek/lermontov/ss4/vol1/poems/345.html) встречается `Ты бережной, как пестун` и даже визуально похожая латинская `c` в слове `cнова`; публикация «Тарханов» (https://tarhany.ru/lermontov/proizvedenija/stihotvorenija_1837_1839/posvjaschenie__1837) даёт `Ты бережно, как пе́стун`. Это **разночтение цифровых свидетелей**, а не разрешение агенту выбрать «более грамотное» слово и подписать его чужим изданием. Зафиксировать выбранный свидетель/издание, проверить спорное место по факсимиле или академической печати; смешение латиницы и кириллицы внутри слова помечать как `mixed_script_word` и отправлять на редакционную проверку. Самостоятельная нормализация произношения не меняет опубликованный цитатный текст.

### Read-only контроль конкретного цитатного Short

Для этого специального режима доступен **непубликующий** CLI:
    python scripts/validate_poetry_quote_shorts.py path/to/quote-packet.json
После человеческого прослушивания финального MP4 / аудио — отдельно:
    python scripts/validate_poetry_quote_shorts.py path/to/quote-packet.json --require-audio-review

JSON-пакет версии 1 должен фиксировать: project_key, poet, work; edition (author/work/citation/version/url/state); sources (не менее двух явно указанных разных URL и классов); edition_lines, excerpt_lines и excerpt_start_line (строки *подряд*), tts_lines с разрешёнными только ударениями, full_comment_lines; pronunciation_notes (token/stressed/sense); format_mode=short_two_comments, short_description, pinned_comment, history_comment; audio_review.status=unverified до фактического прослушивания. Дополнительно — author_playlist и other_playlists из канонического allowlist. Поле \`audio_review.status=reviewed\` требует digest и reviewer, но **не доказывает** само по себе, что звук действительно проверен: оператор обязан прослушать каждую строку, особенно окончания и ударения. Использовать этот пакет для фиксации решения, **не** как источник самих цитат: академические издания проверяются человеком.

Старый \`validate_legendary_poet_package_v31.py\` продолжает проверять **ровно пять блоков обычного пакета**. Новый CLI предназначен только для утверждённого владельцем режима цитатных Shorts с двумя комментариями; применять старый five-block валидатор к этому исключению ошибочно. Он также не заменяет права доступа, лицензионные проверки и independent public readback.

## 6. ЗАКРЕП

**500–900 символов**. Первая строка `*«Точное название»* — Имя Поэта, проверенный год` (жирным **только название**). Далее 1–2 абзаца с **новым, проверенным углом**, которого нет в Description; 1–2 точные стихотворные строки, каждая на своей строке в `_..._`; конкретный вопрос с **двумя вариантами ответа**; две строки релевантных плейлистов. **Без хештегов.** Если владелец отдельно попросил полный оригинальный текст в закрепе, сверить текст и лимит комментария; запрос владельца может изменить краткий формат, но не достоверность.

## 7. ТЕГИ

Строка `ТЕГИ: тег1,тег2,...` — 15–25 тегов, ≤480 символов, **запятая без пробела**. Порядок: поэт → произведение/инципит → ключевая строка → год → эпоха/направление → тема → канал. Запрещены «видео», «музыка», «песня», «стихи», «слушать онлайн», «скачать», «hd», «новинка» и нерелевантные жанры.

## Локальная механическая проверка перед copy/paste

Новый пятиблочный пакет v3.1 можно проверить **без доступа к YouTube**:

```powershell
python .\scripts\validate_legendary_poet_package_v31.py .\copy.txt
```

Скрипт читает пять блоков кода без языковой метки и проверяет ограничения длины, порядок ссылок, зарегистрированные URL, одинарные маркеры `*жирный*` / `_курсив_`, плейлисты, хештеги и теги. Он **не проверяет** исторические сведения, подлинность стихотворных цитат, содержание видео, формат реального отображения и не авторизует никаких изменений публикаций. Важное ограничение: проверка предназначена **только для нового ручного пакета v3.1**, не для обработки старых описаний.
