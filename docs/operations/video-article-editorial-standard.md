# Source-led video article editorial standard

Версия: `video-article-editorial-v1`  
Статус: обязательный review standard для The Legendary Poet

## Назначение

Для каждого значимого полного видео проект может выпускать связанный комплект:

```text
видео YouTube/VK
→ глубокая статья на thelegendarypoet.ru
→ краткий VK wall post
→ source ledger с проверяемыми claims
```

Статья создаётся не ради механического наращивания ключевых слов. Её задача — дать читателю точный текстологический и историко-литературный контекст, показать границу между фактом и интерпретацией и направить к первоисточникам.

## Обязательные файлы

```text
content/video-articles/<slug>.md
content/video-articles/<slug>.sources.json
content/wall-posts/<slug>.txt
content/wall-posts/<slug>.sources.json
```

## Front matter статьи

Обязательны:

- `title`;
- `slug`;
- `status`;
- `poet`;
- `work`;
- exact `youtube_video_id`;
- exact `vk_video_id` после подтверждённой загрузки;
- `seo_title`;
- `meta_description`;
- короткий список релевантных `keywords`.

`status` до человеческой вычитки остаётся `editorial-review`. Draft URL нельзя публиковать на стене как существующую страницу.

## Иерархия источников

1. Академическое или авторитетное издание текста произведения.
2. Авторские примечания, письма, дневники и публицистика.
3. Цифровые фонды государственных библиотек, архивов и музеев.
4. Академические комментарии и исследования.
5. Популярные справочные материалы — только как дополнительная навигация.

Поисковая выдача, пересказы без библиографии и автоматически сгенерированные страницы не являются достаточным основанием для фактического утверждения.

## Claim ledger

Каждое проверяемое утверждение получает:

```json
{
  "claim_id": "stable-machine-id",
  "claim": "Проверяемое утверждение",
  "source_ids": ["primary-source-id"]
}
```

Каждый `source_id` обязан существовать в массиве `sources` и содержать:

- тип источника;
- ясное название;
- абсолютный URL;
- достаточную точность, чтобы редактор мог проверить claim без поиска по всему интернету.

Один общий список ссылок без связи с утверждениями не считается source ledger.

## Граница факта и анализа

Факты формулируются только в пределах источника. Нельзя автоматически:

- уточнять мотивы поэта;
- превращать спорную идентификацию образа в установленный факт;
- добавлять легенды о создании произведения;
- приписывать автору современную политическую позицию;
- делать биографический вывод по одной поэтической строке.

Смысловые выводы обозначаются формулой `Редакционное прочтение:` либо другим явно различимым маркером. Авторское примечание и исследовательская интерпретация не смешиваются.

## Рекомендуемая структура

1. Сильное введение без шаблонной фразы «это не просто».
2. Что именно представляет собой произведение: стихотворение, цикл, поэма, глава.
3. Даты и история создания — только при наличии источников.
4. Композиция и движение образов.
5. Авторское пояснение или контекст, если существует.
6. Отдельно маркированное редакционное прочтение.
7. Связь с музыкальной версией The Legendary Poet.
8. Краткий FAQ из реальных поисковых вопросов, без повторения текста абзац в абзац.
9. Первоисточники и академические материалы.
10. Редакционная прозрачность.

## SEO без переспама

- Один основной поисковый интент на страницу.
- Название произведения и автор присутствуют в H1, SEO title и meta description естественно.
- Подзаголовки отвечают на отдельные вопросы читателя.
- Не повторять одну ключевую фразу в каждом абзаце.
- Не добавлять нерелевантных поэтов, произведений и жанров.
- FAQ отвечает содержательно, а не переставляет слова из заголовка.
- Канонический URL и Open Graph metadata добавляются на уровне сайта при публикации.
- Внутренние ссылки ведут на страницу поэта, произведение, музыкальное видео и связанные проверенные статьи.

## Связь со стеной VK

Wall post — не копия всей статьи. Он содержит:

- сильный заголовок;
- 2–4 смысловых абзаца;
- exact video attachment;
- одну ссылку на опубликованную статью или, пока её нет, одну ссылку на сайт;
- 3–5 наиболее важных первоисточников;
- ограниченный набор релевантных hashtags.

Каждый URL из wall source JSON должен быть видим в сообщении ровно один раз. Ссылка на The Legendary Poet также встречается ровно один раз.

## Публикационный gate

Статья и пост могут перейти из draft в публикацию только после проверки:

- exact video IDs;
- всех claim/source связей;
- корректности цитат и дат;
- отсутствия неподтверждённых биографических утверждений;
- различимости факта и интерпретации;
- работоспособности ссылок;
- соответствия wall message и wall source JSON;
- свежего VK snapshot и duplicate scan перед `wall.post`.

Автоматический executor форматирует и проверяет структуру, но не принимает литературные решения за редактора.
