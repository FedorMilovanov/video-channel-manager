# @lordchrist — Telegram presentation v2

Дата утверждения: 2026-08-07  
Policy ID: `lordchrist-editorial-v2`

Этот слой отвечает только за визуальную подачу Telegram. Immutable source queue `verified-30-posts.json` и её digest не меняются.

## Правила

1. Абзацы source quote сохраняются дословно.
2. Если в теле есть прямые фрагменты `«…»`, **жирным** становится самый длинный прямой фрагмент; при равной длине выбирается первый из них.
3. Остальные прямые фрагменты становятся *курсивом*.
4. Если прямой речи нет, renderer не выдумывает body emphasis.
5. Автор — **жирным**.
6. Название труда — *курсивом*.
7. Видимый `©` не публикуется.
8. Перед hashtags остаётся дополнительный пустой ENTER (`\n\n\n` после attribution).
9. Hashtags сохраняются без изменения.
10. Provider encoding — Telegram HTML; source symbols HTML-escaped.
11. После `sendMessage` exact bold/italic entities проверяются в UTF-16 offsets.

## Почему v2

Правило v1 «первая прямая речь = bold» оказалось слишком механическим. Например, следующий autonomous post `lordchrist-bunyan-fire-grace` начинается вопросом `«Что это значит?»`; выделять этот короткий prompt жирным хуже, чем смысловой ответ о Христе. v2 выбирает содержательную длинную реплику детерминированно, без ручного редактирования source queue.

## Durable proof

До provider mutation exact rendered payload сохраняется рядом с dispatch evidence в `state/lordchrist-telegram`. `provider_payload_sha256` покрывает plain text, HTML, policy digest и expected formatting entities.

После отправки `published/verified` допускается только при exact chat identity, exact plain text, exact reviewed bold/italic entities и positive `message_id`. Любое postflight mismatch после возможной отправки становится `unknown/may_exist`; blind resend запрещён.
