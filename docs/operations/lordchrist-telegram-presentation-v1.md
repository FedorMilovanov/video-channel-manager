# @lordchrist — Telegram presentation v1

Дата утверждения визуального правила: 2026-08-07  
Issue: `#163`  
Policy ID: `lordchrist-editorial-v1`

Этот документ показывает **presentation layer**, а не заменяет source queue. Источник и перевод остаются в `content/telegram/lordchrist/verified-30-posts.json`; этот слой определяет только визуальную подачу Telegram message.

## Короткое правило

Для каждого поста:

1. сохранить абзацы цитаты без редакторских переписываний;
2. первый прямой фрагмент `«…»` в теле сделать **жирным**;
3. каждый последующий прямой фрагмент `«…»` в теле сделать *курсивом*;
4. если прямых фрагментов нет — тело не раскрашивать искусственно;
5. автор — **жирным**;
6. название труда — *курсивом*;
7. `©` в опубликованной attribution не показывать;
8. между attribution и hashtags оставить дополнительный пустой ENTER;
9. hashtags не менять.

## Образец №2 — несколько реплик

Source body:

> Толкователь взял Христианина за руку и привёл туда, где у стены горел огонь. Рядом стоял человек и непрестанно лил на него воду, желая погасить; однако огонь разгорался всё выше и жарче. Христианин спросил: «Что это значит?»
>
> Толкователь ответил: «Этот огонь — действие благодати, совершённое в сердце; тот, кто льёт воду, стараясь угасить и уничтожить его, — дьявол. Но поскольку ты видишь, что огонь всё же горит выше и жарче, тебе будет показана причина».

Presentation rule:

- **«Что это значит?»** — первое прямое высказывание;
- *«Этот огонь — действие благодати …»* — второе;
- все дальнейшие прямые `«…»` — *italic*;
- **Джон Беньян**, *«Путешествие Пилигрима»* — attribution.

## Образец без прямой речи

Если в двух-трёх quote paragraphs нет ни одного `«…»`, renderer не выбирает произвольное предложение для emphasis. Тело остаётся plain. Внизу всё равно применяются:

**Автор**, *«Название труда»*


#Хэштеги #Сохраняются

## Почему policy хранится отдельно от source queue

Первый canary уже опубликован и связан с source payload SHA. Поэтому визуальное правило не должно изменять verified translation/source evidence и не должно пересчитывать утверждённый queue digest.

Presentation v1 создаёт отдельный exact provider payload со своим SHA. До `sendMessage` этот rendered payload должен быть сохранён в durable state рядом с source dispatch.

## Verification rule

После `sendMessage` проверяются не только `message_id` и текст. Для formatted publication Telegram обязан вернуть точные expected `bold` / `italic` entities с offsets/length в UTF-16 code units.

Дополнительные provider entities (`hashtag`, etc.) допустимы, но reviewed formatting не может исчезнуть или сдвинуться.

Любое несовпадение formatting после возможной отправки переводит operation в `unknown / may_exist`; automatic resend запрещён.
