# The Legendary Poet — сбор всех MP3/WAV для ручного отбора

Дата: 2026-11-14. Операторский сценарий для локального ПК; **не** запускается на GitHub Actions и не имеет права записывать в интернет, на сайт или в Telegram.

## Правило источников

MP3 и WAV с одинаковыми названиями могут быть разными мастер-версиями. **Не выбирать лучшую по имени, размеру или битрейту без прослушивания.** Полные дубликаты определяются по SHA-256, а не по названию; WAV и MP3 одной музыкальной версии не считаются точными дубликатами.

Исходники никогда не перемещаются и не удаляются. Сначала отчёт; затем можно копировать все версии в одну папку под существующей директорией «Легендарный поэт» для ручного выбора. Файлы из Downloads, с дисков и из других рабочих мест остаются на месте. Никакой автоматической очистки Downloads, переименования исходных файлов, перекодировки или удаления не предусмотрено.

## Использование на Windows

Требуется Python 3.11+; файл: `scripts/collect_legendary_poet_audio.py`.

**Указать существующий реальный путь** к папке «Легендарный поэт» на компьютере. Ниже `D:\Легендарный поэт` — пример, а не утверждение, что такая папка существует.

Сначала просмотр всего доступного пространства, без копирования:

```powershell
py -3 scripts/collect_legendary_poet_audio.py --target "D:\Легендарный поэт\_АУДИО_НА_ПРОСЛУШИВАНИЕ" --all-drives --include-flac
```

Отчёты в целевой папке:

- `_АУДИО_КАТАЛОГ.csv` — все найденные оригинальные пути, SHA-256, расширение, размер, новый путь, статус;
- `_АУДИО_СВОДКА.json` — число разных записей, полных дублей, размер уникальных файлов, ошибки.

После проверки отчёта и свободного места — безопасное **копирование** всех уникальных аудиофайлов:

```powershell
py -3 scripts/collect_legendary_poet_audio.py --target "D:\Легендарный поэт\_АУДИО_НА_ПРОСЛУШИВАНИЕ" --all-drives --include-flac --copy
```

Для небольшого поиска вместо всех дисков задавай точные корневые каталоги:

```powershell
py -3 scripts/collect_legendary_poet_audio.py --target "D:\Легендарный поэт\_АУДИО_НА_ПРОСЛУШИВАНИЕ" --root "$HOME\Downloads" --root "E:\VideoChannelManager" --copy
```

### Что выполняется фактически

- Рекурсивный поиск `.mp3`, `.wav`, и `.flac` только с `--include-flac`.
- Не проходит Windows, Program Files, AppData, кеши, node_modules, git и симлинки; не заходит повторно в целевой каталог.
- Первая найденная запись каждого SHA попадает в общую папку, её имя получает суффикс короткого SHA. Два аудио с одним названием, но разными SHA, остаются **двумя версиями**.
- Дубли с тем же SHA видны отдельными строками CSV со всеми первоначальными расположениями.
- В режиме `--copy` временный файл проверяется SHA до финального имени. Повторный запуск не размножает файлы. При проблемах файлы не удаляются, а ошибка отражается в CSV.
- Только после личного прослушивания владелец указывает, какая версия утверждена; дальше выполняется уже существующий стандарт `FedorMilovanov/TheLegendaryPoet/docs/MUSIC_RELEASE_WORKFLOW.md`.

### Операционные ограничения

Сканирование всех дисков при больших Downloads может занять значительное время. Убедиться в свободном месте — при копировании могут понадобиться многие гигабайты. Если где-то находятся повреждённые или недоступные файлы, их ошибки учитываются, но остальные продолжают обрабатываться.

Скрипт **не гарантирует**, что найден каждый оригинал в Suno: облачные, не скачанные на компьютер генерации нельзя обнаружить поиском файловой системы. Их следует включить отдельным облачным каталогом с идентификаторами генераций, а скачивать только после выбора нужного варианта.

Не удалять «мусор» на основе одного возраста, расширения, имени файла, одинакового звучания или одинокого пути. Сначала собрать полную карту, затем пользователь выбирает, что можно убирать после резервной копии.
