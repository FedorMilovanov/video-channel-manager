# VK deferred editorial review — операционный регламент

Канал: **The Legendary Poet**  
Сообщество: `235216998`

## Назначение

Этот этап проверяет фактологические и чувствительные формулировки, которые техническая волна описаний намеренно не переписывала.

Маркер означает только «проверить». Он не доказывает ошибку и не разрешает автоматическое исправление.

## Встроенная локализация

Новые editorial plans сохраняют для каждого маркера:

- точные совпавшие слова;
- абзацы, в которых они находятся;
- семейства триггеров;
- тип проверки.

Для старого завершённого plan builder повторно локализует маркеры по тем же детерминированным правилам на проверенном final snapshot.

## Дедупликация

Бот объединяет только побайтно идентичные текущие описания.

- одинаковое описание нескольких роликов образует одну research unit;
- все VK IDs и ссылки сохраняются внутри группы;
- похожие, но не идентичные описания никогда не склеиваются;
- ID research unit строится из SHA-256 описания.

## Приоритеты

- `P1` — присутствует sensitive claim marker;
- `P2` — присутствует factual review marker без sensitive marker;
- `P3` — маркер не удалось локализовать, поэтому требуется ручная проверка.

Приоритет определяет порядок исследования, а не истинность утверждения.

## One-file handoff

Запуск:

```powershell
pwsh -File .\scripts\Invoke-VkDeferredEditorialReview.ps1
```

Helper:

1. выбирает последний `vk-description-wave-apply-*.zip`;
2. независимо проверяет завершённый apply;
3. извлекает deferred findings и final snapshot;
4. локализует точные места проверки;
5. объединяет только идентичные описания;
6. создаёт JSON, Markdown, HTML и CSV;
7. упаковывает всё в один `vk-deferred-editorial-review-*.zip`;
8. не вызывает VK mutation API.

Внутри ZIP:

- `review-queue.html` — основной фильтруемый интерфейс;
- `review-queue.md` — полный читаемый отчёт;
- `review-queue.csv` — рабочий чек-лист;
- `review-queue.json` — машинный источник истины;
- `manifest.json` — размеры и SHA-256;
- `README.txt` — краткая инструкция.

## Следующие волны

Работа идёт последовательно:

1. исследование `P1` по авторитетным источникам;
2. исследование `P2`;
3. разбор `P3` и ложных маркеров;
4. отдельный correction-only plan только для доказанных изменений;
5. correction dry-run;
6. внешняя проверка одного ZIP;
7. guarded execute;
8. независимый postflight и финальный snapshot.

Correction plan не может менять названия, альбомы, memberships или состав видеотеки. Каждая текстовая правка должна иметь точный video ID, before/after SHA-256, источник и reviewed decision.

## Запрещено

- считать маркер найденной ошибкой;
- автоматически переписывать факты;
- объединять приблизительно похожие описания;
- создавать correction plan без источников;
- выполнять correction сразу после исследования без dry-run;
- редактировать VK Studio параллельно с writer.
