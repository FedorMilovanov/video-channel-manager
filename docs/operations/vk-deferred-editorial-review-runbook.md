# VK deferred editorial review — операционный регламент

Канал: **The Legendary Poet**  
Сообщество: `235216998`

## Назначение

Этот этап проверяет фактологические и чувствительные формулировки, которые техническая волна описаний намеренно не переписывала.

Маркер означает только «проверить». Он не доказывает ошибку и не разрешает автоматическое исправление.

## Содержательный текст и технические поверхности

Активные маркеры строятся только по содержательному тексту. До поиска исключаются:

- URL;
- известные footer-строки;
- хэштеги;
- декоративные линии;
- пустые технические строки.

Это предотвращает ложные чувствительные срабатывания. Например, `#БессмертныйПолк` больше не считается утверждением о смерти или self-harm только из-за подстроки `смерт`.

## Встроенная локализация

Новые editorial plans сохраняют для каждого маркера:

- точные совпавшие слова;
- абзацы, в которых они находятся;
- семейства триггеров;
- тип проверки.

Старый завершённый plan остаётся неизменным и подписанным. Review builder повторно классифицирует каждый его маркер относительно проверенного final snapshot и исходного reviewed-before текста.

Используются три статуса:

- `present_in_final` — утверждение присутствует в финальном содержательном тексте;
- `legacy_not_present_in_final` — старый маркер находился только в удалённой технической поверхности или отсутствует после технической очистки;
- `legacy_unlocalized` — старый маркер сохранён для аудита, но точный фрагмент невозможно восстановить детерминированно.

Ни один legacy-статус не блокирует создание review-only ZIP и не разрешает correction.

## Дедупликация

Бот объединяет только побайтно идентичные текущие описания.

- одинаковое описание нескольких роликов образует одну research unit;
- все VK IDs и ссылки сохраняются внутри группы;
- похожие, но не идентичные описания никогда не склеиваются;
- ID research unit строится из SHA-256 описания.

## Приоритеты

- `P1` — активный `sensitive_claim_review` со статусом `present_in_final`;
- `P2` — активный `factual_editorial_review` без активного sensitive marker;
- `P3` — только legacy-маркеры или ручная классификация.

Приоритет определяется финальным содержательным текстом, а не историческим числом маркеров в старом плане.

## One-file handoff

Запуск:

```powershell
pwsh -File .\scripts\Invoke-VkDeferredEditorialReview.ps1
```

Helper:

1. выбирает последний `vk-description-wave-apply-*.zip`;
2. независимо проверяет завершённый apply;
3. извлекает deferred findings, reviewed before-state и final snapshot;
4. локализует активные и legacy-маркеры;
5. объединяет только идентичные финальные описания;
6. создаёт JSON, Markdown, HTML и CSV;
7. упаковывает всё в один `vk-deferred-editorial-review-*.zip`;
8. не вызывает VK mutation API.

Внутри ZIP:

- `review-queue.html` — основной фильтруемый интерфейс;
- `review-queue.md` — полный читаемый отчёт;
- `review-queue.csv` — рабочий чек-лист;
- `review-queue.json` — машинный источник истины;
- `manifest.json` — размеры и SHA-256;
- `README.txt` — краткая инструкция.

## Инцидент `-235216998_456239132`

Старый plan содержал `sensitive_claim_review` для ролика «Внимая Ужасам Войны... ⚡ КОРОТКАЯ ВЕРСИЯ ⚡ Николай Некрасов».

Причина старого срабатывания: 11-й хэштег `#БессмертныйПолк` содержал подстроку `смерт`. Техническая волна ограничила хэштеги десятью и удалила этот тег. В финальном описании чувствительного утверждения нет.

Правильная классификация:

```text
sensitive_claim_review: legacy_not_present_in_final
priority: P3
remote writes: 0
```

## Следующие волны

Работа идёт последовательно:

1. исследование активных `P1` по авторитетным источникам;
2. исследование активных `P2`;
3. разбор `P3`, legacy и ложных маркеров;
4. отдельный correction-only plan только для доказанных изменений;
5. correction dry-run;
6. внешняя проверка одного ZIP;
7. guarded execute;
8. независимый postflight и финальный snapshot.

Correction plan не может менять названия, альбомы, memberships или состав видеотеки. Каждая текстовая правка должна иметь точный video ID, before/after SHA-256, источник и reviewed decision.

## Запрещено

- считать маркер найденной ошибкой;
- автоматически переписывать факты;
- назначать `P1/P2` по хэштегам, URL или footer;
- терять старый маркер из аудита только потому, что его нет в final text;
- объединять приблизительно похожие описания;
- создавать correction plan без источников;
- выполнять correction сразу после исследования без dry-run;
- редактировать VK Studio параллельно с writer.
