## Почему не загрузили восемь кандидатов немедленно

1. Свежий owner-YouTube API scan по `legendary-poet` **упёрся в OAuth refresh HTTP 400**. Токен не переназначался и никаких YouTube uploads не осуществлялось. Независимый публичный HTML YouTube доступен, но он не заменяет owner AuditPackage.
2. Публичная страница VK не дала точный, проверяемый перечень video IDs для сравнения. Отсутствие ID в HTML **не означает отсутствие видео в VK**.
3. Для `lord-god-strength` старый VK user-token `legendary-poet` карантинирован после code 9 (Issue #662). Его обход/повторный flood не допускается. VK app `54555649` требует поддерживаемого OAuth consent и последующего отдельного точного preflight, прежде чем открывать новый writer.
4. Последняя восьмёрка YouTube — это **источники на проверку VK**, а не безусловный список для загрузки. Ранее опубликованные видео нельзя дублировать.

## Instagram-грамматика «Господь Бог»

Основной формат — вертикальный **Reel**: исходный Short либо один смыслово законченный фрагмент существующей проповеди. Начало отвечает на один богословский вопрос, затем идёт обоснованный ответ из **действительной проповеди**, с корректным именем проповедника и контекстом. Не обрезать обоснование ради провокационного заголовка. Для полного видео — ссылка и атрибуция; для дословной цитаты из Писания — подтверждённая редакция перевода и стих.

Пайпер, Спроул, МакАртур, Вошер, Бики и другие авторы в исходных YouTube-записях требуют **отдельной проверки прав на кросспостинг аудио/видео**. Локальная возможность скачать ролик, наличие его на собственном YouTube и техническая совместимость MP4 **не дают автоматически** права републикации на Instagram. Сохраняем редакционный приоритет, но без мнимого правового допуска.

## Правило завершения

- `source_found` — найдено на YouTube.
- `target_presence_unverified` — на VK ещё не проверено (не «отсутствует»).
- `target_absence_confirmed` — возможно лишь после полного подходящего VK readback, с учётом обычных видео и отдельной поверхности Clips.
- `publisher_ready` — ровно один source ID, проверенный проект и получатель, доказанно новый объект, исходные байты/rights, неизменяемый план и актуальная авторизация.
- `provider_verified` — только если удалённый ID, видимость и durable receipt подтверждены после записи.

Цель — не создавать ещё десять отдельных конвейеров: использовать **существующий `vk-native-video-wave-v2`**, `video-manager instagram media-route / production` и долговечные журналы. Read-only доказательства нельзя превращать в разрешение на provider writes.
