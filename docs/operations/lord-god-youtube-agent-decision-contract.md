## Заголовки и авторство

Для нового согласованного Lord God Short используется *русский Title Case только для смысловых слов*: короткие предлоги и частицы в нижнем регистре, разделитель между названием и именем ведущего — пробел, ASCII дефис `-`, пробел. Не копировать поэтический шаблон из `docs/youtube-metadata-package-master-v3.1.md` (пять вариантов, CAPS внутри заголовка и др.). Каноническое имя — **Джон МакАртур**, включая склонения **МакАртура**, **МакАртуром**; недопустимо «Макартур». Важнее шаблона точность: название должно соответствовать произнесённому фрагменту. **Существующий публичный заголовок не переименовывать** в рамках description-only задачи без отдельного утверждения точного after-title. Это отдельная provider-операция и отдельный postflight.

## YouTube-native выделения: правильная граница пунктуации

Сырые маркеры YouTube: `*жирный*`, `_курсив_`. Двойной Markdown `**жирный**` — ошибка. Завершающий выделенную фразу знак **внутри** закрывающего маркера, когда он относится к выделенной фразе:

| Не отправлять | Исправленная смысловая граница |
| --- | --- |
| `_греческий текст сохранился_, но ...` | `_греческий текст сохранился,_ но ...` |
| `_не оправдывать себя_, однако ...` | `_не оправдывать себя,_ однако ...` |
| `*27 января 1983 года*.` | `*27 января 1983 года.*` |
| `*Источник*: https://example.org` | `*Источник:* https://example.org` |
| `* Деяния 17:11 *` | Исправить пробелы; **не ставить цифровой таймкод/стих в жирный маркер, если YouTube преобразует его в `**17:11**`** |

**Не все внешние знаки являются дефектом.** В `*Джон МакАртур* — проповедник` тире соединяет части предложения и остаётся вне выделения. При сомнении о семантической границе — редакционная проверка, а не механический перенос запятой. YouTube может преобразовать `1:05:51` или `17:11` внутри жирного блока в `**...**`; после записи проверять **raw `textOriginal` и публичный рендер**. При расхождении — новый осмысленно исправленный текст после read-only сверки, никогда слепой повтор PUT.

## Предотвращение повторных ошибок в работе агентов

**Перед отправкой любого Description** сверить **в таком порядке**:

1. Правильный `project_key`, owner `channel_id`, точный существующий `video_id`, current remote `main` и отсутствие конкурирующего writer. Не использовать устаревшую локальную ветку, alias как доказательство identity, историю чата как live-state.
2. Две первые **непустые raw-строки** содержательны и не содержат `*`, `_`, URL и технических заголовков; далее — умеренные жирные заголовки и курсив. Пунктуация внутри выделения по смыслу. Текст **не превышает 5000 UTF-8 байт**, не 5000 Unicode-символов.
3. Для Shorts полная русская запись — первая подтверждённая URL до социальных ссылок; для длинного видео — **не повторять self-link**, английский оригинал в правильном длинном формате. Не перенимать The Legendary Poet порядок двух верхних плейлистов. Проверить корректность `МакАртур`, регистрацию ссылок и отсутствие дубликатов.
4. Собрать точные `before` / `after`, source ledger, snapshot title/description, live tags, category, audio/default languages, `status.privacyStatus`, `publishAt`, все `localizations` (названия и описания), ссылки/таймкоды/плейлисты. Не удалять источник или права ради красоты.
5. Прогнать `presentation_issues`, `source_preservation_issues`, `forward_longform_editorial_issues` и `validate_youtube_description`, увидеть человекочитаемый diff и получить текущую approval/write authority. Факт `PASS` не означает разрешение на upload/publish.
6. **Только штатная current-main `video-manager youtube apply-copy-fixes`**, по **одному signed-плану на один ID**, с внешними `--confirm-target`, `--confirm-after-sha256`, уникальными backup/result и собственным блокирующим lock. Без одноразовых несовместимых провайдерных клиентов и повторной загрузки MP4.
7. После PUT проверить через независимый owner GET **все** зафиксированные локализации, language, title, tags, status/schedule, description, exact full URL, два preview-рядка, комментарии и отдельно — delayed locale drift. **HTTP 200 / CLI PASS ≠ вся приёмка**. При неопределённом результате `HOLD` без повторного PUT.
8. Для комментариев — до отправки `validate_comment_text` и фактологическая сверка; ранее созданный owner comment изменяется по **старому comment_id**, не создаётся заново. Закрепление доступно только в YouTube Studio и проверяется отдельно. Для Shorts кликабельный `Related Video` задаётся только в Studio с отдельным разрешением; URL в Description сам не гарантирует тап.

**Границы нуля:** `COPY_FORMAT_PASS`, `COMMENT_PASS`, `RIGHTS_APPROVED`, `MEDIA_LISTENING_PASS`, `PROVIDER_WRITTEN_VERIFIED`, `RELATED_VIDEO_STUDIO_CONFIRMED`, `PINNED_STUDIO_CONFIRMED` — **независимые статусы**. Не объявлять весь выпуск или канал завершённым по одной зелёной проверке.

Исторические SHA, снимки и результаты из Issue #795 — доказательства прошлого, **не** текущее состояние API. Действующие проверки исходного кода и примеры остаются в профильных документах, которые перечислены выше.
