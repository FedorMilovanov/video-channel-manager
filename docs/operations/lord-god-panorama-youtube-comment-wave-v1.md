# «Панорама Библии» — защищённая публикация комментариев через Wave Engine

**Проект:** `lord-god-strength` · **GitHub:** issue #795 · **YouTube owner:** `UCeSJsC6go2c9pdJCuUI1BYA` · **OAuth alias:** `fedor-milovanov`.

## Назначение и ограничения

Модуль `wave_engine/youtube_comment_provider.py` регистрирует **только** операцию `youtube.comment.create` с policy `lord-god-panorama-comment-wave-v1`. Путь выполняет один заранее рассмотренный комментарий для одного публичного видео; он **не публикует автоматически** черновики и не возрождает завершённый `scripts/apply_youtube_comment_plan.py`.

Исходный файл с текстом должен быть зафиксирован как артефакт в `WaveSourceEvidence`. Затем строятся строго типизированные `WavePlan` и `WaveApplyIntent`, связанные с его SHA-256 и проектом. CLI `video-manager wave apply` допускает этот провайдер только при **одной** операции, двух подтверждениях `--enable-provider-writes` и `intent.enable_provider_writes`. CI по умолчанию закрыт; требуется отдельный точный CI-токен из `ci_operator_confirmation_for(plan)`.

Перед исполнением сверяются: точный `channel_id`, единственная OAuth-принадлежность по `channels.list(mine=true)`, полное текущее название и публичность видео, правильный первоисточник `slovo.org`, контрольная сумма уже одобренного комментария, отсутствие любых авторских top-level комментариев на видео. Используется общий локальный замок YouTube, чтобы два писателя не работали одновременно. Приложение повторно проверяет запись по данным владельца.

Каждая операция получает собственный журнал `WaveEngine` **до начала возможной отправки POST**. Если исход отправки или постпроверки неизвестен, автоматическое повторение запрещено. Строгая инвентаризация отклоняет неполный JSON, неопределённого автора, несовпадающий video ID и повторяющиеся токены страниц. Даже успешный ответ POST не считается подтверждением: отдельная полная owner-GET инвентаризация должна вернуть ровно один авторский комментарий с совпадающими ID и текстом. Это подтверждение со стороны владельца, не независимое доказательство публичной видимости. `wave reconcile` выполняет только GET для установления наличия ровно одного комментария от точного владельца с точным текстом; отсутствие или дубликаты требуют расследования вручную.

## Стадии редакции

Редактор заранее сверяет текущую речь проповедника, библейские места и первоисточник. Каждый комментарий должен тематически дополнять конкретную лекцию, а не повторять её описание. Оформление: обычный текст, отдельные абзацы, YouTube-native `*полужирный*` и `_курсив_`, без Markdown `**...` и без искусственных вопросов в конце.

**Только после отдельной редакционной приёмки** комментарий переводится из `REVIEW_ONLY` в `review_status=approved` в однооперационном пакете и получает актуальный `reviewed_at`. Сам факт создания черновика, GitHub issue или публикации описания видео **не является** разрешением на комментарий. В пакете должна присутствовать `source_url` реальной страницы этой лекции, а та же ссылка — в теле комментария.

Предусмотрены только создание **первого** комментария и его GET-only reconciliation. Второй комментарий на том же видео, обновление, удаление, ответы, закрепление, переводы и любые иные операции здесь намеренно **не поддерживаются**. Для них требуется отдельная спроектированная и проверенная процедура; прямой вызов `commentThreads.insert` из операторского скрипта вместо Wave Engine запрещён.
