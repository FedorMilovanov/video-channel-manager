# Календарь выпусков @lordchrist и почему Иуда не вышел

Состояние на 21.11.2026. Документ фиксирует факты, а не разрешения: публикация запускается
только владельцем, у меня в токене нет прав на переменные репозитория.

## 1. Что случилось со статьёй Иуды

Факты, проверенные по репозиторию, ledger и запускам workflow:

- В очереди: `lordchrist-telegraph-jude-1-5-20261105`, `status: ready`, дата **2026-11-15**.
- У записи есть `slot_override_reason`: оператор сознательно поставил **воскресенье 15.11** —
  вне обычного слота, с пометкой, что выпуск делает ручной `workflow_dispatch`.
- Расписание `lordchrist-telegram-poster.yml` — только Пн/Ср/Сб; в воскресенье оно не запускается,
  то есть автоматически Иуда выйти не мог по построению.
- Ручного запуска по Иуде не было: последний release-запуск 15.11 в 18:09 МСК выпустил
  другую статью (`lordchrist-telegraph-peasants-1525`, сообщение 1619).
- В ledger `state/lordchrist-telegram` записи по Иуде **нет вообще** — Telegraph-страница
  не создавалась, сообщения не было. Это не удалённый пост, а никогда не выпущенный.
- `due --now 2026-11-21` отвечает `no_article_scheduled_today`: просрочка нигде не всплывает.
  Ровно поэтому статья и «зависла на несколько недель» — система знает только «сегодня»,
  а не «что пропущено».

**Вывод:** текст готов (есть редакционный аудит 05.11 и утверждённый блоб), блокирует только
не сделанный ручной выпуск. Никакого технического дефекта в статье нет.

## 2. Почему не выходят Чарнок 06–09

- Их даты (10.11, 13.11, 17.11, 20.11) лежат в `charnock-reschedule-2026.json`.
- `lordchrist-charnock-scheduled-reissue.yml` запускается по `cron` Пн/Ср/Сб фактически
  только вторник/пятница 09:00 UTC и **требует точного совпадения даты** с манифестом.
  Окно 12:00–13:59 МСК, catch-up запрещён — поэтому прошедшие даты не «догоняются».
- Ручной dispatch этого workflow принимает **только 09–12**, значит 06, 07 и 08 можно
  выпустить лишь запланированным запуском в свой день.
- Манифест закреплён переменной `LORDCHRIST_CHARNOCK_RECOVERY_MANIFEST_SHA256`; менять файл
  без обновления переменной нельзя — workflow отвергнет запуск.

## 3. Что уже сделано (этот цикл)

- `scripts/lordchrist_telegraph_backlog.py` — read-only отчёт: что опубликовано, что просрочено,
  что без даты, что держит календарь Чарнока, и предложение дат с шагом по умолчанию 3 дня,
  не более одной статьи в день. Пишет только необязательный JSON, провайдера не касается.
- `.github/workflows/lordchrist-release-backlog.yml` — ежедневный (09:17 МСК) read-only отчёт
  в summary запуска. Просрочка больше не может «тихо» накопиться: она видна каждое утро.
- `charnock-reschedule-2026-proposal-20261121.json` — **черновик**, не действующий манифест:
  06 → 08.12, 07 → 11.12, 08 → 15.12, 09 → 18.12 (вторники и пятницы, свободные от 10–13).

## 5. Точные шаги для Иуды (владелец, 22.11)

```bash
# 1. Разрешить ручную полосу и привязать ровно эту статью
gh variable set LORDCHRIST_TELEGRAPH_POSTING_ENABLED --body true
gh variable set LORDCHRIST_TELEGRAPH_APPROVED_PUBLICATION_ID \
  --body lordchrist-telegraph-jude-1-5-20261105
gh variable set LORDCHRIST_TELEGRAPH_APPROVED_ARTICLE_BLOB_SHA \
  --body dd15da234a74eb474963d275c6a9bccfcadb9985

# 2. Один запуск: страница Telegraph + один пост в канал, с квитанциями в state-ветке
gh workflow run lordchrist-telegraph-poster.yml --ref main \
  -f action=publish \
  -f publication_id=lordchrist-telegraph-jude-1-5-20261105 \
  -f confirm=PUBLISH:lordchrist-telegraph-jude-1-5-20261105
```

Проверка после запуска: в `state/lordchrist-telegram` появилась запись с `telegraph_path`
и `telegram_message_id`; публичный GET страницы отдаёт заголовок
««ИИСУС» ИЛИ «ГОСПОДЬ»? ОДНО РАЗНОЧТЕНИЕ В ИУД. 1:5»; в канале одно новое сообщение.
Повторный запуск запрещён: второе сообщение не появится, но и «догонять» слот не нужно.

Перед выпуском стоит перечитать `…/jude/lordchrist-telegraph-jude-1-5-20261105-audit.md`:
там честно записано, что полного комментария Хоутона в открытом доступе нет и что
стилистическая правка не меняла позицию.

## 6. Точные шаги по Чарноку 06–09 (владелец)

```bash

cp content/telegram/lordchrist/telegraph-v1/charnock/charnock-reschedule-2026-proposal-20261121.json \
   content/telegram/lordchrist/telegraph-v1/charnock/charnock-reschedule-2026.json
# (в коммите убрать из файла поля proposal_status/proposal_note — это уже не черновик)

# 2. Пересчитать SHA-256 и обновить переменную
sha256sum content/telegram/lordchrist/telegraph-v1/charnock/charnock-reschedule-2026.json
gh variable set LORDCHRIST_CHARNOCK_RECOVERY_MANIFEST_SHA256 --body <новый sha256>

```

Дальше — по датам: 08.12, 11.12, 15.12, 18.12. Запуск идёт по `cron` в окне 12:00–13:59 МСК;
ручной `workflow_dispatch` для 06–08 невозможен по устройству workflow.

## 7. Что не делать

- Не ставить две статьи на одну дату и не «догонять» пропущенные слоты пачкой.
- Не менять даты 10–13 без нового манифеста.
- Не снимать HOLD с №13 до независимой приёмки цитат.
- Не публиковать 04 и 05 без сокращения: они у потолка payload.
