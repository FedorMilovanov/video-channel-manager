# Переиздание qc-редакций Чарнока на существующих страницах

Дата: 21.11.2026. Владелец: `@FedorMilovanov`. Один запуск — одна страница.

## Что это

QC-редакции 13 бесед Чарнока лежат в репозитории в виде JSON-источника (ветка `main`,
редакции `charnock-XX-qc-20261121`). Живые страницы Telegraph всё ещё несут прежние
редакции. Переиздание заменяет **всё тело** уже опубликованной страницы полезной
нагрузкой, собранной из reviewed JSON, по тому же Telegraph path, с тем же автором.
Новых страниц не создаётся, Telegram не трогается, публичный URL не меняется.

## Манифест

`content/telegram/lordchrist/telegraph-v1/charnock/charnock-qc-reissue-20261121.json`
фиксирует для каждой страницы:

- `publication_id` и `article_path` + `article_git_blob_sha` (проверенный блоб);
- канонический живой `path`/`url` (для 01b, 02, 03, 04 — исправленные издания от 05.11,
  на которые уже указывают сообщения канала; для остальных — исходные публикации);
- прежний заголовок, время публикации и ссылку на сообщение канала — для оператора.

## Запуск

Workflow: `Lordchrist Charnock QC reissue of existing Telegraph pages (owner only)`
(`.github/workflows/lordchrist-charnock-qc-reissue.yml`), только `workflow_dispatch`,
только владелец, только `main`, попытка №1, HEAD не должен сдвинуться.

1. `page=<ключ>`, `mode=dry-run`, `confirm=REISSUE_EXISTING_CHARNOCK_PAGE_ONCE`.
   Публичный GET, сборка payload, план: прежний и новый заголовок, число блоков,
   байты до/после, первые расхождения. Провайдер не вызывается, квитанции нет.
2. `page=<ключ>`, `mode=execute`, тот же `confirm`. Один POST `editPage/<path>` с
   `return_content=true`, затем публичный readback.

## Гарантии

- Отказ, если живой path не совпадает с закреплённым, автор не «Господь Бог»,
  страница уже совпадает с payload (тогда `--reconcile`), payload больше 65 536 B,
  квитанция с таким именем уже есть, токена нет или аккаунт не владеет страницей.
- Между подготовкой и POST — второй публичный GET; любое вмешательство отменяет запись.
- Один POST. Ошибка/таймаут → квитанция `UNCERTAIN`, повтор запрещён.
- Readback: точное совпадение узлов или семантическое (теги + видимый текст, без атрибутов
  картинок) с равным числом узлов и совпадающим заголовком. Иначе `UNCERTAIN`.
- Ровно одна квитанция на запуск (`charnock-qc-reissue-<page>-<sha16>[-uncertain]-<run_id>.json`),
  выгружается артефактом; каталог квитанций создаётся вне git-репозитория.

## Ограничения

- `editPage` не атомарен: гонка между последним GET и POST возможна; поэтому второй GET.
- Slug остаётся прежним и может не совпадать с новым заголовком — это ожидаемо.
- 04 (64 435 B) и 05 (64 304 B) у потолка: перед любой правкой текста сначала сокращать.
- Telegram-канал не редактируется: HOLD №13 сохраняется.

## Статус на 21.11.2026

Процедура выполнена для всех 13 страниц: 01b — `execute` + независимый `reconcile`,
02–13 — `execute`; каждый запуск вернул `VERIFIED_REISSUE` (`01b` —
`VERIFIED_REISSUE_RECONCILED`) и ровно одну квитанцию. Постраничные номера запусков,
байты и live SHA — `docs/audits/2026-11-21-charnock-qc-reissue-execution-log.md`.

Для повторной проверки уже опубликованной страницы используйте `mode=reconcile`:
он ничего не записывает у провайдера, только читает публичную страницу и пишет квитанцию.
