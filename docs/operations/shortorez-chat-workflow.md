# SHORTOREZ — direct chat-agent video cutting from an already voiced source

**Entry point:** owner writes `SHORTOREZ: <video URL>` to an AI agent with access to the owner's authorized computer. **This is a direct-chat operator workflow, NOT a Telegram MP3Bot `/mode`, NOT `SHORTS FACTORY MAX`, NOT a newly supported one-command renderer, and NOT a publishing authorization.** SHORTOREZ cuts an already finished video in the existing spoken language the owner wants (including Russian-dubbed material), without creating a new translation unless the owner separately requests it.

This is the single discovery/routing document for chat agents. Existing media/editorial implementation stays where it is: the MP3Bot repository's media libraries and direct-agent handbooks, and Video Channel Manager's `shortorez_routing.py` for provider-inert platform *planning*. Do not duplicate either engine or add a provider writer. Owning cross-platform issue: [VCM #940](https://github.com/FedorMilovanov/video-channel-manager/issues/940); platform specifics: [shortorez-publication-routing.md](shortorez-publication-routing.md).

## What the owner can ask

Example: `SHORTOREZ: https://youtu.be/k2Fh8aJfhOA — разобрать все вопросы и ответы; сделать смысловые Shorts и подходящие длинные выпуски, без перевода и без публикации.`

- A URL is an **intake**, not a guaranteed accessible source file or permission to redistribute. Resolve the real video/channel, inspect local existing media and choose the exact already-voiced master by path, SHA-256, duration and stream probe. Check the actual spoken language. Reuse accepted existing bytes, captions and audio evidence; do not download, remux or render duplicates unnecessarily.
- **No default cap of five Shorts or three long clips.** Review every complete topical unit/question. Produce as many individually justified, useful standalone pieces as source content and operator scope support. Do not produce filler or the same passage multiple times with different titles to inflate the count.
- **No new translation:** cut the existing spoken soundtrack in the owner's intended language. For a Russian-dubbed source use *that actual audible mixed track*; for an original-language source requested as-is, do not invent a translation prerequisite. Do not invoke Yandex, VoxCPM2 or TTS unless there is a separately requested and reviewed audio-repair task. If the source is not ready in the requested language, report the dependency; do not silently change languages or send the user into Bot Factory mode.
- Working transport is authorized Desktop Commander / local shell in a non-disruptive manner. Do not open or control the owner's visible browser, steal focus, read cookies, stop Bot production or interfere with other worktrees/agents. See [nonintrusive-desktop-and-browser-rule.md](nonintrusive-desktop-and-browser-rule.md).

## Correct processing sequence

1. **Inventory first.** Read repository `AGENTS.md`, this contract, `mp3telegrambot/docs/agent_direct_dubbing/README.md`, `CLIPS_SHORTS_AND_HANDOFF.md`, and only relevant case/renderer docs. Verify current Git branches, active agents, files already rendered, available disk space, source rights and the exact owner channel/project. Keep media outside Git.
2. **Full editorial coverage.** Examine the video, owner chapters and transcript/ASR as *clues*, then inspect the actual audible source-language audio. For Q&A, enumerate **all questions and answers**. Separate chapter timestamps from verified semantic start/end times; distinguish introduction, question, answer, Scripture context and conclusion. Make an internal source-bound inventory before any render.
3. **Exact candidate boundaries.** For each passage, prove that the first complete spoken word and final syllable survive. Hear 3–8 seconds before the start and 2–3 seconds beyond the proposed end; ensure no negation, qualification, Scripture reference or subsequent sentence is severed. A fixed duration (30/60/180 seconds) must not choose the semantic endpoint. For translated sources, track any dubbing offset from original captions to the *actual translated postmix*; never reuse a historical +600ms constant blindly.
4. **Select deliverables.** A vertical Short is a complete standalone thought, Q&A or excerpt up to the actual destination cap; a longer answer, chapter or independent argument can receive a horizontal 16:9 cut as needed, even beyond 15 minutes when genuinely justified. Preserve the full context rather than force every answer into 180 seconds. Default to original speaking speed 1.00x.
5. **Choose composition by the actual scene:**  
   - Solo speaker / sermon / lecture: **edge-to-edge 9:16 full-bleed without blurred duplicate background**. One fixed horizontal crop for **each original camera shot** and an immediate crop change on the *source camera cut*. No per-frame face chasing or artificial smooth pan by default. Review whether a fixed crop loses essential content.
   - Two concurrently relevant faces / interview / Q&A / important diagrams: retain necessary subjects; a centered full 16:9 image with synchronized moving blurred padding, or another specifically reviewed composition, may be correct. Never apply this multi-speaker default to a solo preacher.
   - Long horizontal editions remain 16:9 with source framing. Do not stretch pixel aspect ratios or invent image detail.
6. **Reuse owned media functions.** Check the current-main repository-owned video renderer/FFmpeg wrappers and source-bound export interface; do not create another batch uploader, render engine or temporary version family. In `mp3telegrambot`, `services/shortorez_export.py` is the narrow reviewed **177–300 second** local export capability and `services/shortorez_vk_variant.py` is the optional VK derivative. Neither is a general end-to-end link importer. Use only when its actual constraints match the accepted input. A missing reusable capability is a documented engineering blocker, not permission to bypass identity, quality or no-overwrite guards.
7. **QA each final encoded MP4, not merely the plan.** Inspect opening and ending audio on headphones/actual playback, all joins and significant camera changes; source meaning and names, audio synchronization, aspect/safe zones, frame samples, final codec/streams, playable decode, duration and SHA-256. Separate `TECH_QA_PASS` from `LISTENING_QA_PASS` and `EDITORIAL_APPROVED`. Final speed-changed audio requires independent listening; ASR/ffprobe alone never proves natural speech.
8. **Clean local handoff.** Keep plans, internal SRT, manifests and QC reports in `C:\Users\Fedor\Projects\video-channel-manager\operator-output\shortorez-<source_id>` or another reviewed work directory; only accepted, human-readable Russian-named MP4s belong in Downloads as the user requested. No physical duplicate media, blind overwrite, default ZIP/version explosion, or fabricated `ready` status. Give exact paths, counts, source digest and any holds.
9. **Publish only as a separate approved phase.** A finished local cut is not clearance to upload. Check rights for editing/rehosting, exact destination community/account, existing duplicate/processing/draft states, current platform limits, locked write intent, provider-effect journal and exact readback. Never automatically publish just because a link was supplied.

## Separate presentation / publication routing (not an automatic upload)

- **YouTube Shorts / VK native Clips:** vertical or applicable square video, actual duration at most 180 seconds unless the provider's current rules establish otherwise. VK native Clips are not ordinary VK Video edits.
- **Instagram Reels API:** historically allowed up to 900 seconds under the reviewed contract; verify the live API/account rules and format before planning upload. Telegram native video is not arbitrarily limited to 180/300 seconds; actual transport limits are checked separately.
- **Speed adjustments:** at the owner's explicit opt-in only, a VK-only 1.05x/1.10x/1.15x/1.20x pitch-preserving copy of a **complete** accepted interval may fit 180 seconds. Keep a 1.00x original for TG/IG. Never silently speed up, chop off necessary context or call an accelerated technical pass a listening pass.
- `src/video_channel_manager/shortorez_routing.py` only **plans** destination variants; it does not accept arbitrary project accounts, render MP4s, publish, schedule or override review/rights. Reuse existing per-provider Video Manager writers only after separate, exact operation authorization. Include a correctly attributed full source link where requested.
