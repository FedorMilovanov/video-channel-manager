# Повторяемый аудит YouTube

Этот процесс читает данные канала и создаёт локальные отчёты. Он не изменяет YouTube.

## 1. Получить свежий AuditPackage

```powershell
video-manager youtube scan --account legendary-poet
```

Команда выводит точный путь к JSON в `data\exports\`.

## 2. Дополнить снимок геометрией исходных видео

`#Shorts` и длительность недостаточны для точной классификации. Для владельца канала YouTube Data API может вернуть `fileDetails.videoStreams` с шириной и высотой исходного файла.

```powershell
python .\scripts\enrich_youtube_file_details.py `
  .\data\exports\youtube-legendary-poet-UC-78ys2S3cQ3lpqgXfo-SvQ-20260724-202430.json `
  --account legendary-poet
```

Будет создан новый файл с окончанием:

```text
-file-details.json
```

Это только локальное обогащение. Скрипт делает read-only `videos.list` и не пишет на YouTube.

Если для отдельных старых видео `fileDetails` недоступны, они останутся в статусе `needs_review` и не должны участвовать в автоматическом удалении из плейлистов.

## 3. Создать детерминированный редакционный отчёт

```powershell
python .\scripts\audit_youtube_editorial.py `
  .\data\exports\youtube-legendary-poet-UC-78ys2S3cQ3lpqgXfo-SvQ-20260724-202430-file-details.json `
  --output .\data\reports\youtube-editorial-audit.md
```

Отчёт считает:

- точные дубликаты названий;
- подтверждённые Shorts и спорные кандидаты;
- Shorts, находящиеся в плейлистах;
- полные видео без плейлистов;
- лимиты названий и описаний;
- пустые и слишком короткие описания;
- лишние переносы;
- чрезмерно длинные абзацы;
- маркеры форматирования в первом абзаце;
- отдельные шаблонные формулы;
- высокоуверенные ошибки пунктуации рядом с выделением.

Это эвристический отчёт, а не ChangePlan. Он не проверяет литературные факты и не разрешает изменения.

## 4. Провести фактологическую проверку

Для каждого реально редактируемого описания создать внутренний source ledger:

```text
video_id
claim
status: confirmed | disputed | unsupported | interpretation
source_title
source_url
source_note
```

Использовать приоритет источников из [`youtube-editorial-standard.md`](youtube-editorial-standard.md).

## 5. Подготовить предложения

Предложения разделяются на независимые группы:

1. фактические исправления;
2. названия;
3. структура и форматирование описаний;
4. tags и хэштеги;
5. добавление полных роликов в плейлисты;
6. удаление подтверждённых Shorts из плейлистов;
7. очистка описания канала.

Нельзя смешивать все группы в одну непрозрачную массовую операцию.

## 6. Создать ChangePlan

Только утверждённые владельцем предложения превращаются в ChangePlan. До write-фазы обязательны:

- точные remote ID;
- исходное значение;
- новое значение;
- expected revision;
- причина и источник;
- validation;
- dry-run;
- читаемый diff;
- лимит размера пакета;
- повторное чтение после применения;
- журнал результата.

## 7. Запреты

- Не определять Shorts только по `#Shorts`.
- Не удалять членство из плейлиста по длительности.
- Не переписывать все названия одним шаблоном.
- Не применять результат скрипта напрямую.
- Не расширять OAuth scope без отдельного этапа реализации и проверки.
- Не добавлять секреты, токены, AuditPackage и локальные отчёты в Git.
