# Чарнок — восстановление библиографических подписей №11–13 (кандидаты, 23.11.2026)

**RESEARCH_ONLY / CANDIDATE / NO_RELEASE_AUTHORITY / NO_PROVIDER_WRITE / TELEGRAM_SEND_HOLD_13**

Публичный read-only HTML-аудит 13 существующих страниц Telegraph установил, что
на живых страницах №11, 12 и 13 отсутствует заключительный источниковый абзац
«© Цитаты Чарнока … Gutenberg #53527». В reviewed Markdown он существует,
но в оригинальном JSON, из которого формировался provider payload, его нет.
Старый renderer скрывал эту ошибку, подставляя подпись из Markdown.

## Объекты и идентичность

| Статья | Неизменный approved JSON blob SHA-1 | Кандидат |
|---|---|---|
| 11 | `d42392bb593de4f89d36a12a3548f459efe41090` | `charnock-11.json` |
| 12 | `e7ea215bcea907747363f41dc0bc4443f58269a8` | `charnock-12.json` |
| 13 | `eedc00889bb2e907bbcc91de914d8ddf68f1737c` | `charnock-13.json` |

Проверяемые `.md` лежат рядом с approved JSON по каноническому пути
`content/telegram/lordchrist/telegraph-v1/charnock/lordchrist-telegraph-charnock-{11,12,13}.md`.
Эти Markdown-файлы не менялись; именно с ними candidate JSON должен совпадать
при прямом рендеринге без заимствования готового ©-абзаца.

Изменения кандидатов ограничены явно кандидатными полями `revision`,
`metadata.updated_at` и **ровно одним последним библиографическим блоком**.
Исторические citation blocks, `sources`, обложки, медиа и source-anchors сохранены.

## Не путать при приёмке

- Наличие этой папки **не** меняет Git blob approved JSON, immutable queue,
  manifest, одобренные даты, state ledger или те же Telegraph URL.
- Статьи 11–13 **всё ещё отсутствуют в source-complete состоянии на живых
  Telegraph-страницах**, пока отдельный санкционированный editPage и полный
  readback не подтвердят новый текст. Не выдавать sidecar за live proof.
- №13 сохраняет отдельный Telegram SEND HOLD, независимо от источникового
  подвала, исправленных купюр q-3/q-19 и механических тестов.
- №10–12 сохраняют release source-binding/media-base HOLD. Новую версию нельзя
  перепривязывать к защищённым слотам без owner/editorial review и no-replay.
- Любая внешняя публикация требует также решение о правах на перевод и
  соответствующий проверенный primary-source provenance.

## Регрессионный контракт

`tests/test_charnock_article_md_consistency.py` проверяет 13 reviewed
JSON↔Markdown пар: canonical для 01b–10 и sidecar для 11–13. Для трёх
последних отдельно проверяет **буквальное сохранение approved blob SHA**,
равенство всех старых блоков, неизменность evidence, медиа и источников,
а также фиксацию существующего расхождения live JSON / reviewed Markdown.

`scripts/charnock_article_edit.py` больше не должен оставлять JSON обновлённым
после отказа Markdown-рендера. Пять интеграционных regression tests проверяют
в том числе восстановление обоих файлов при сбое второй замены и сохранение
исходного JSON в отдельном `.rollback`-файле, если повторный `os.replace`
тоже отказывает. В таком случае ошибка содержит точный путь резервной копии
для ручной сверки/восстановления. **Это не атомарная транзакция для двух файлов
при аварийном отключении питания**; `README`/тесты не должны обещать абсолютной
атомарности.

## Уникальность адресов редакционных блоков

При независимом аудите обнаружены совпадающие top-level `block_id` у добавленных
библиографических подвалов и ранее существовавших абзацев. У кандидатов они
исправлены **только в последнем добавленном блоке**, без изменения печатного
текста, источников, кавычек, медиа, канонических JSON и живых страниц:

- №11: новый подвал `p-27` (ранее конфликтовал с существующим `p-26`);
- №12: новый подвал `p-21` (ранее конфликтовал с существующим `p-20`);
- №13: новый подвал `p-23` (ранее конфликтовал с существующим `p-20`;
  `p-21` и `p-22` также заняты).

Тот же `p-27` закреплён в отдельном кандидате перевода №11 q-10.
Регрессионные тесты проверяют уникальность ID в кандидатах и то, что
новые ID отсутствуют в одобренных старых версиях. Это подготовка
редакционного материала, **не** разрешение `editPage` или Telegram POST.

## Права и авторство: граница текущего аудита

Исходный английский текст Чарнока относится к историческому произведению;
Project Gutenberg #53527 отмечает его как public domain в США, а само
произведение относится к изданию 1853 года. Ссылка на Gutenberg полезна
для воспроизводимой атрибуции, но сама по себе не удостоверяет права
на конкретный новый русский перевод и изображения.

В `media_slots[].copyright_provenance` обложки помечены как созданные через
Arena battle mode, без идентификатора исходной модели, условий конкретного
провайдера и исходной квитанции создания. Перед снятием правового HOLD
нужны доказательства допустимого использования выбранных обложек и
подтверждение происхождения русского перевода. Общие условия Arena
(https://help.arena.ai/articles/5629909088-terms-of-use) отдельно
предупреждают об условиях сторонних AI-сервисов; статус «оператор выбрал
картинку» не является юридической лицензией.

Ни один из этих пунктов не открывает автоматическую отправку.

**Следующий разрешённый этап:** независимая редакторская проверка sidecar
→ per-URL guarded provider dry-run → отдельное решение владельца об in-place
исправлении с no-replay → полный публичный live readback → новая
квитанция. До этого этапа PR остаётся Draft.
