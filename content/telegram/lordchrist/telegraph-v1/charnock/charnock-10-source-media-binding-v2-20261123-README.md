## Безопасная схема

Отдельный файл `charnock-10-source-media-binding-v2-20261123.json` связывает старые исходные идентификаторы **и** новый целевой source/media contract. Его Git blob `7708abcac315acd32794dfdc52e4676278a85c81` зашит в код как дополнительная защита от неутверждённого редактирования. **Старый manifest и исторический ledger не переписываются.** Защитный SHA старого manifest в GitHub Actions продолжает проверяться.

Для **ровно №10** исполнитель:
1. проверяет байты старого manifest и нового versioned binding по Git blob;
2. проверяет совпадение ID, даты 24.11.2026, исходного сообщения 1600, URL, исходных source/cover SHA и старого origin commit с историческим ledger;
3. проверяет текущие Git blob статьи и обложки, SHA статьи, SHA нормализованного дерева и 97 узлов; использует QC media-base `c1bafa...`;
4. при **публикационном** `prepare` проверяет удаление старого сообщения и весь текущий публичный Telegraph, и только затем создаёт необратимую **durable claim**;
5. при `send` дополнительно проверяет source binding на той же версии, фиксирует один message ID и проводит публичный GET; не повторяет неопределённый provider effect.

В workflow сначала та же версия binding применяется при read-only `scheduled_reissue_preflight_status`, поэтому дублирующие запуски после `verified` не считают новый receipt устаревшим.

**№06–08 не восстанавливаются задним числом. №09 уже VERIFIED (новый message 1630), его не повторять. №11–12 без своей версионированной авторизации останутся fail-closed. №13 остаётся SEND HOLD.** Репозиторий MILOVI, установленный task и runtime копия не меняются.
